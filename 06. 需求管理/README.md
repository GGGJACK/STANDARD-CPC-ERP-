# 需求管理

本目錄存放**可追溯、可評審、可驗收**的產品與開發需求，不放歷史代碼快照、測試結果或正式業務數據。

## 目錄分類

| 目錄 | 職責 |
|---|---|
| `PRD/` | 產品需求、業務流程、權限、數據規則及驗收標準 |

後續如增加獨立需求，可按相同方式分類；重大業務規則變更應在相關 PRD 留下版本與決策記錄。

## 使用規則

1. 原始業務資料先轉為具備需求編號的 PRD，再進入開發。
2. 業務狀態、責任域、角色代碼及單據術語以 PRD 為準，避免各自命名。
3. `DEC-*` 是待業務決策項，未確認前不得把假定規則當成正式財務邏輯。
4. 需求變更應更新追溯矩陣與修訂記錄，不直接刪除舊需求編號。
5. 測試結果放 `04. 四期/測試設計_*/`，缺陷放 `00. 仓库管理/defects.csv`，不要混入本目錄。
