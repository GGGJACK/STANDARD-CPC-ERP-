## ERP 复刻项目资产上传（完成）

**目标**：把 1GB 业务数据 + 288MB 源码上传到项目资产库，供团队协作。

**关键发现**
- 1GB 数据在 `F:\03 Standard CPC DataBase`（1014 MB / 2038 文件），其中 `03. 附件` 占 943 MB / 2024 文件（PurchaseOrder 633M、Quotation 197M、Product 66M）
- 代码在 `F:\04 STANDARD CPC SYSTEM`（288 MB / 493 文件），但**绝大部分是重复的 data.db**：
  - `04. 四期/系统代码/data.db` 与 `03. 三期/系统代码/data.db` **MD5 完全相同**（`ebf073784c61a3299bcded3784874a61`）
  - 真实代码（server.mjs + lib/）只有约 1.7 MB
- `04. 四期/系统代码/data.db` 存在 1.6 MB 未 checkpoint 的 `data.db-wal`

**技术方案（可复用）**
- 资产库只能**单文件**上传，三步：`file_upload`（拿凭证）→ `curl -T` 流式 PUT → `file_upload_complete`（必须，否则不落库）
- 大文件/多文件场景必须**分箱打包**：按业务对象切成独立可解压的 zip，单包 ≤250 MB，不做分卷
- 附件类用 `ZIP_STORED`（pdf/mp4 已压缩），代码/数据/文档用 `ZIP_DEFLATED`
- 数据库交付：拷 db+wal+shm 三件套到暂存区，**在副本上** `PRAGMA journal_mode=DELETE` 做 checkpoint，源库不动。本次主库 54,702,080 → 54,820,864 字节（+118,784）

**踩坑记录**
1. `curl --data-binary "路径"` 会把路径字符串当内容上传且返回 0 —— 必须用 `-T`
2. `file_upload` 的 `file_size` 必须是精确字节数
3. 签发的 access key 偶发失效（`InvalidAccessKeyId` / 403）：本次 ERP-05_C 首次失败，重新取凭证即可；**凭证拿到后要立刻上传并立刻 complete**，中间隔太久会报「任务不存在」
4. 下载签名 URL 偶发同样报 `InvalidAccessKeyId`，重试即可
