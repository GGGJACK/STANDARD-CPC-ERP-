2. 九個決策與取捨

改動前以每輪 3 題向業務方確認，避免「照字面做但不符合實際」。以下同時記下為什麼這樣選。

問題決定理由與影響
回收桶形態統一 /trash ＋各列表「回收筒」切換（雙入口）會議要「一個垃圾桶頁面」，但原系統其實是各列表內切換。兩者都保留：全局可搜可篩，模組內隨手可達。代價是兩套入口共用同一份資料與權限。
庫存刪除對象產品檔案／調整單／盤點單各刪各的三種記錄語義不同，混在一個「刪除」會讓賬說不清。產品刪除只影響檔案，不動歷史調整單。
回收桶權限辦公室可還原＋永久刪除，每日 10 條；超出拒絕並通知管理層辦公室最常誤刪，讓其自救；但永久刪除不可逆，用日限額＋通知做護欄，不剝奪能力。
合約彈窗欄位對齊原系統 13 個業務欄＋保留文件上傳原系統 EditContract 本來就沒有客戶 ID／報價單 ID；保留 ID 只會讓填表人困惑。但舊資料要靠 ID 關聯，所以轉隱藏欄位。
合約列表超連結編號→合約詳情、客戶名→客戶詳情與原系統 ViewPurchaseOrder／ViewCustomer 的連結習慣一致，減少學習成本。
PO 帶工作單位PO → 報價單 → 合約 逐級反查902 張 PO 有 898 張自帶 work_unit_name，剩下 4 張只能靠鏈路；合約本身沒有 work_unit 欄位（見 §3），所以鏈路是唯一可行解。
「前往排班」只跳 /schedules原系統就是 <Link to="Schedules"> 不帶參數；會議也確認照原系統。要定位可用 ?date=&po=（已支援，只是不自動）。
已過賬盤點刪除自動反向沖銷 → 回收桶；還原時重新過賬直接刪會讓庫存憑空多／少；只在回收桶「永久刪除」才動賬太晚。兩邊都生成調整單，賬可追。
CSV 匯出全站僅管理層會議原話「其他會計、辦公室、前線全部刪掉」。已同步處理直接訪問 URL 的 403，避免只藏按鈕。

3. 原系統源碼核查（先查再改）

3.1 回收桶：不是獨立頁面

全站前端 bundle（05. 源碼分析/frontend，app.js 836 KB ＋ 30 個 chunk）只有 送貨單 實作了軟刪除。相關代碼在 chunks/DeliveryNotes-Cg9Qulrc.js：

  • is_deleted: !0 → toast「已移至回收筒！」；is_deleted: !1 → 「已還原送貨單！」
  • 工具列：回收筒 切換鈕；正常視圖 移至回收筒 (n)；回收視圖 還原 (n)／永久刪除 (n)
  • 確認框帶條數：確定要將 n 個送貨單移至回收筒嗎？、確定要永久刪除 n 個送貨單嗎？此操作不能還原。
  • 空狀態：回收筒沒有送貨單
結論與會者記憶中的「原系統有回收桶頁」其實是送貨單列表內的切換視圖。本輪保留這套勾選批次語法，再疊加統一頁與「回收時間／操作人」——不是憑空發明，也不是照抄一個不存在的頁面。

3.3 合約表單與資料真相

schema.json 的 Contract 實體只有 18 個欄位（含 id／建立時間），沒有 work_unit、contact_person、contact_phone；但 EditContract 的 UI 有「工作單位（From）」，值寫在 notes 的排程文件 JSON 裡。這解釋了兩件事：

  • 為什麼「選 PO 帶工作單位」不能只查合約——多數歷史合約根本沒這個欄位；
  • 為什麼本輪保留系統自己的 work_unit_name 欄位（新資料才有），並用報價單做中間鏈路。

EditContract 的 UI 分段是：基本資料（合約編號／PO 編號／客戶名稱 To／工作單位 From／工作地點／工作內容／合約名稱自動生成）＋排程文件資料（Attn／Date／From／From Tel／Contract No／服務描述／每月服務日期／底部備注）＋合約條款（起訖／頻率／總額／付款／狀態／備註）。本輪取「業務必要」的前後兩段，跳過只為列印排程文件的中段。

由 chunk 文案可還原版面：總報價單／已接受報價／總收入 三張 KPI；報價記錄／合約列表／送貨單記錄／報告文件／合約文件／PO文件 六個頁簽；左側聯絡人（姓名＋電話）；空狀態「暫無報價記錄／暫無合約記錄／暫無送貨單記錄／暫無文件」。本輪按此重做，頁簽改為伺服器端 ?tab=，保留原本的辦公室時間窗與查看額度檢查。

附錄 B 排障 FAQ

Q1. 改了程式但畫面沒變？

Node 不會熱載。關掉啟動視窗重開，瀏覽器 Ctrl+F5。若仍舊，確認你改的是 04. 四期\系统代码，不是三期或 _歷史版本。

Q2. 回收桶裡 45 筆是什麼？可以清掉嗎？

來源系統本來就軟刪除的 30 張報價＋15 張送貨單。可永久刪除，但建議先備份 data.db。

Q3. 為什麼辦公室刪到第 11 條就失敗？

每日限額 10 條（還原＋永久刪除合計）。系統會寫一則通知到「管理後台 → 告警」，管理層可代為處理或等次日重置。

Q4. 合約的客戶 ID 不見了，會不會影響舊資料？

不會。ID 仍在表單的 hidden 欄位中提交；prepareRecord 只覆蓋有提交的欄位。詳情頁與列印都不再顯示它。

Q5. 盤點刪除後庫存變了，是 bug 嗎？

是設計。已過賬盤點要先沖回盤點前數量，否則刪單會讓賬面多／少貨。可在「調整記錄」看到「自動沖銷」那張單。

Q6. 車輛費用頁不見了，怎麼查全部費用？

點車牌進彈窗，選「全部年份」；或開 /view/vehicles/:id。費用資料沒有刪除，只移除重複入口。

Q7. 驗收腳本可以對正式庫跑嗎？

不行。腳本會寫入並刪除記錄，且有 :3101 守門。請複製 data.db 到 _verify.db，用 PORT=3101 啟動副本再跑。
