【2026-10-25 下午補丁：補給／請假存不了】
  症狀：/mysupply 按「新增記錄」→ 填完按「建立記錄」→ 沒有成功提示，記錄也沒出現。
  根因：新增彈窗把預先產生的 ID 同時寫進 __id 與 __new_id，後端因此認為你要
       「編輯一筆不存在的記錄」，直接丟 404；錯誤訊息又被第二次 404 蓋掉，
       使用者只看到空白頁。
  影響：請假紀錄用同一個彈窗，一樣存不了；辦公室代建補給也受影響。
  修法：core.mjs 的 __id 改空；actions.mjs 對壞 __id 回退為新增；
       server.mjs 錯誤重繪前先確認記錄還在。
  驗證：新增 驗收_補給請假存檔.mjs（18 項全過），並用真實瀏覽器走完一次新增。
  另修：明細裡的產品選擇只回填名稱、product_id/unit 一直空白 → 已一併回填；
       列表的「產品／工具」欄原本顯示 JSON 展開器 → 改為「產品 / 數量」小表。

【2026-10-25 下午第二個補丁：數量只能是整數】
  需求：產品與數量不能有小數（2.5 瓶沒有意義）。
  做法：
    前端 數量欄位改 text + inputmode=numeric，input 時把 2.5 截成 2、-3 截成 3
    後端 assertIntegerQuantities() 檢查，直送 2.5 會回 400「必須為整數，不可有小數」
    歷史 既有記錄該值沒被改動就放行（原系統匯入的小數庫存 204.5 仍能存檔）
  覆蓋：補給／報價／帳單／送貨單／服務報告的明細數量、產品庫存數量、庫存調整數量
  未覆蓋：盤點單的實際數量（4,853 項裡有 40 筆歷史小數，硬性要求會讓舊盤點改不動、完成不了）
