6核心機制詳解

6.1 可搜尋選擇器 picker

一個 .pk 容器同時包含：隱藏輸入（真正提交的值）、文字輸入（顯示／輸入關鍵字）、下拉面板、（多選時）標籤區。

<div class="pk" data-source="contracts" data-multi="0" data-valuemode="id">
  <input type="hidden" class="pk-val" name="contract_id" value="69a93eab…">
  <input type="text"   class="pk-input" value="C-2026-0001 · 城市清潔有限公司">
  <div class="pk-menu" hidden></div>
</div>

三種 valueMode（最容易踩坑的地方）

模式隱藏欄存什麼用在哪些欄位
id（預設）記錄 ID排班工作列表的 po_id / contract_id、車輛費用（若保留 id）
label顯示文字工作單位、產品名稱、藥物名稱、分配員工的單筆值
text輸入框即時鏡像客戶名稱、工作內容、車牌、員工姓名、工具名稱——允許自由輸入，選中則覆蓋
為什麼需要 text 模式 像「客戶名稱」這種欄位，歷史資料可能不在客戶庫裡。若用 id 模式，用戶打了字但沒選中任何一筆，隱藏值仍是空的，存檔就會丟資料。text 模式讓輸入框內容實時同步到隱藏欄，既能選、也能手打。

填充鏈（選一個合約 → 自動帶出 8 個欄位）

pkApplyFill() 會在同一個 .wf-card（或整個 form）範圍內，把所有 [data-f="欄名"] 與 [name="欄名"] 找出來逐一賦值，並派發 input 事件，讓 items 編輯器的 row 物件同步更新。

兩個已修掉的坑（改動時別改回去） ① 不能填充「自己這個 picker」的隱藏欄與文字框——否則選合約後，contract_number 的 fill 會把「C-2026-0001 · 城市清潔有限公司」這串 label 寫進只該放編號的欄位（本輪實測踩過）。 ② 被填充的對象若是另一個 picker 的隱藏欄，必須同時更新它旁邊的文字框，否則畫面上看得到舊值、存進去的卻是新值。

6.2 明細編輯器 items

原本只有一種表格佈局、且所有欄位都會畫出來。現在支援三件事：

能力寫法
隱藏欄欄位定義加 hidden: true；不渲染但 row 物件仍保留，存檔原樣回寫

11二次開發指引

11.1 新增一個 picker 資料源

  1. 在 lib/pickers.mjs 的 PICK_SOURCES 加一項：{ label, build(store) }，回傳 {id,label,sub,text,fill}。

  3. 明細欄位同理，在 itemColumns 加 type:'pick'。
  4. 不需要改 server.mjs——/api/pick 會自動支援新 source（僅做白名單檢查）。

11.2 讓某個實體也支援彈窗

  1. 複製 scheduleDialog()，把 ENTITIES.schedules 換成目標實體、action 換成 /save/<key>。
  2. 頁面上放 <button data-dlg-open="你的id">，並把 dialog 的 id 設成同一個。
  3. 如果需要「編輯」也走彈窗，照 ?edit= 的做法：伺服器端判斷參數 → 預填 row → open:true + 自動 showModal()。

11.3 常見陷阱

  • 新增 select 欄位會自動變成「可輸入的 datalist」，不再強制只能選項；若要嚴格限制，請在 prepareRecord 加白名單校驗。
  • items 的隱藏欄一旦從 itemColumns 刪掉，存檔時該 key 就不會被寫入——正確做法是標 hidden:true，不是刪掉。
  • .pk 的下拉面板用絕對定位，若放進 overflow:hidden 的容器會被裁掉；items 卡片已改為 overflow:visible。
  • 改完 CSS/JS 只需重啟 Node 並在瀏覽器 Ctrl+F5；沒有 build 步驟。
