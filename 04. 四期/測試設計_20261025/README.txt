一、這個包有什麼
----------------
1. ERP測試設計與驗收方案_20261025.html
   主文件。含測試策略、161 條逐項用例（前置/步驟/預期/判定）、38 實體×4 角色權限矩陣、
   5 條業務鏈、缺陷分級與准入標準、本輪 115 項實測基線與 8 個待修缺陷的根因定位。

2. 測試結果_基線.html / .json
   可執行驗收的實測結果。JSON 含每條斷言的 expected/actual/耗時與權限矩陣原始數據。

3. 測試用例清單.csv
   161 條用例的表格版（UTF-8 BOM，Excel 可直接開），带基線 PASS/FAIL，可直接當測試進度表用。

4. 缺陷清單.csv
   本輪 8 個失敗項的等級、現象、實測、根因、修復建議、證據。

5. plan.mjs
   用例唯一資料源。改用例只改這裡，再跑 build-plan.mjs 重新生成 HTML/CSV。

6. run-tests.mjs
   零依賴驗收器。自動做一致性快照、起 :3102 隔離服務、跑 115 項檢查、出報告。

7. build-plan.mjs
   由 plan.mjs + 測試結果生成 HTML 與 CSV。

二、怎麼跑
----------
cd "F:\04 STANDARD CPC SYSTEM\04. 四期\測試設計_20261025"
node run-tests.mjs --port 3102 --keep

跑完看：
  測試結果_基線.html
  _run_<runId>\server.log（服務日誌）

只重建文件、不跑測試：
  node build-plan.mjs

三、安全規則（硬性）
--------------------
- 絕不在 :3000 正式埠跑寫入測試；run-tests.mjs 會拒絕 :3000。
- DB 一律用 VACUUM INTO 的一致性快照，不直接複製 db+wal。
- 測試資料統一加 QA-<runId> 前綴，可反查。
- _run_* 是隔離副本，可手動刪除；F: 盤不支援回收站，Node 的 rmSync 會被安全墊攔截，
  所以腳本不自動刪，請手動清理舊的 _run_* 目錄。
