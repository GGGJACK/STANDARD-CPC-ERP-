第 2 步 · 四条修复

STK-06 · 根因不是「忘了写字段」，是写在了错的时机

原代码在 store.save() 之后才把 system_quantity / difference 写回明细。 但 store.save() 返回的是重新从库里读出来的新对象，改 op.item 只改到内存里的 data.items， saved.items 里始终没有 difference。删除冲销时 item.difference 缺失，回退成 actual − 0 = 12，库存被冲成 0， 而「还原」又会 +12 掩掉第一次的错误 —— 所以它一直没被发现。

// 改法：回填必须在 save 之前
for (const op of operations) { op.item.system_quantity = op.before; op.item.difference = op.difference; }
const saved = store.save(cfg.key, data, { ... });
// 冲销侧改成三档：快照 → system_quantity → 抛 409，不再猜

SEC-01 · 判据仍取自实体 viewRoles，只列显式例外

没有另起一套权限表：PICK_SOURCE_ENTITY 把 11 个数据源映射到实体，用实体自己的 viewRoles 判。 唯一例外写在一处 —— employees 对前线开放，因为补给/请假是前线自己填的表单，而 Employee 实体页只给管理层看。 回填字段再按角色裁：金额只给会计/管理层，前线不返回联络资料；每次调用写一条 action=pick 审计。

SEC-02 · 拦在 fieldInput，而不是 renderValue

可见控件输出 value="" + placeholder="•••••"，原值走一个同名 hidden 提交， 保证「看不见」和「不被清空」同时成立。这条修好后，编辑页、明细、打印走的是不同出口的隐患少了一个。

DAT-03 · 认不出就停下来，不要猜

先按 id 认；认不到才按名称查，命中多条直接 409，让用户从下拉选。 productForAdjustment() 同样处理，同名产品不再取第一条。生产库里 47 份盘点单、0 份已过账，所以没有历史脏数据要回填。
