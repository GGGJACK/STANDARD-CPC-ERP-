一、留下谁的实现

分支采用的我放弃的
feat/perm-hardening picker 分 strict / scrub / open 三级：客户/合约/采购单走 assertEntity，产品与员工不 403 而是裁字段；员工另加 selfOnly（前线只返回自己那条）；demo_mode 默认关闭 我的 PICK_SOURCE_ENTITY + pickFillForRole：对产品一刀切 403，会把前线补给表单的选产品打挂
feat/field-masking 遮罩框用 disabled 且不带 name，原值走 hidden；用 value="•••••" 而不是 placeholder；顺带移除报价表头折扣输入（T0-5） 我的 readonly + placeholder 版：能看不能改，但仍会参与提交，遇到同名 hidden 有风险
feat/data-integrity 抽出 matchUniqueByName() 统一「id 优先 → 名称唯一才认 → 多条 409」；fill() 只补空值不覆盖手填；顺手修了 STK-09 调整单编号；修好 saveStockCount 的回填时机 我的单点修法：只处理了客户，工作单位/员工仍按名字取第一条
我在对方基础上补了一处：reverseStockCount 里若 difference 与 system_quantity 都缺失，抛 409 而不是退回 actual − 0。那条路径会把库存清零，宁可中止。对方版本保留了旧的三参数 num() 兜底。
