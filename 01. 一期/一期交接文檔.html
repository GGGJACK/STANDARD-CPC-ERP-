1 · 怎么跑起来

1.1 三步

  1. 确认这台电脑装了 Node.js 22 或更高版本（命令行执行 node -v 能看到版本号即可）
  2. 双击 F:\04 STANDARD CPC SYSTEM\01. 一期\系统代码\启动系统.bat
  3. 浏览器打开 http://127.0.0.1:3000/login

手机或同事要一起看：让手机连同一个 WiFi，打开 http://电脑的局域网IP:3000/login。 启动时命令行会直接打印这个地址（例如 http://192.168.1.155:3000）。

5.3 权限怎么实现

遮蔽（列表页）

办公室角色在客户列表里，服务端把值换掉再输出，不是用 CSS 藏：

聯絡人   林小姐  →  林XX
電話     2672 6927  →  2672 ****
傳真 / 電郵  →  —（直接不返回）

金额（列表 + 详情）

用同一个判断函数控制，会计与管理层放行，其余一律输出 •••••：

function canSeeAmounts(u) {
  return u.role === 'accounting' || u.role === 'management';
}

办公室员工在报价明细里能看到单价，看不到小计与总额——这是确认过的口径：知道「这项多少钱」， 不知道「这单总共多少钱」。

5.4 配额与静默拦截

打开客户详情→ 10 分钟内重开？
是则不计→ 已用 < 上限？
放行 +1→ 超限：拦截→ 写审计 + 通知管理层
规则实现
计数口径每次打开客户详情 +1；同一客户 10 分钟内重复打开不重复计（防 F5 误伤）
上限每人每日 50 次，存 quota 表，跨零点自然重置
管理员追加后台可「追加 N 次」或直接「改为 N」，立即生效
拦截表现HTTP 200 + 中性文案「資料暫時無法載入，請稍後再試 / 已自動通知技術支援」。不用 403——403 在开发者工具里一眼看出是权限问题，机制就暴露了
同时发生写 audit_log（action=block_quota）+ 写 notifications（谁、第几次、想看哪个客户、IP、时间）
为什么列表要一起打码 如果只限详情、列表仍显示电话，员工不点进去、滚两屏就能抄完 50 个客户——配额一次都不会触发。 两把锁必须同时上，这条规则才是真的。

8.2 上线前必须做完的六件事

  1. SQLite → PostgreSQL，并把权限判断下沉为视图 + 行级安全（RLS）
  2. 附件接 OSS：把 03. 附件 按 表/记录ID/字段 结构上传，索引 CSV 入库
  3. 备份：每日 pg_dump + 附件增量到 OSS；办公室电脑用 rclone 每日拉一份到机械盘； 做「超 24 小时无备份即告警」；两块盘轮换

  5. 账号：替换演示账号，按真实名单开号，首次登录强制改密

9 · 给接手开发者

9.1 文件结构

01. 一期/
├─ 一期交接文檔.html        本文件
└─ 系统代码/
   ├─ 启动系统.bat          双击运行（不要移动位置，要和下面三个文件放一起）
   ├─ server.mjs           全部后端逻辑（路由 + 权限 + 配额 + 审计）
   ├─ seed.mjs             从 02. 数据导出 的 JSON 重建数据库
   └─ data.db              SQLite 数据库（已含 1,608 客户等真实数据）

9.2 加一个新模块的四步

  1. 在 seed.mjs 里建表并写入数据（字段名沿用原系统，便于对照）
  2. 在 server.mjs 加两个路由：列表 /xxx、详情 /xxx/:id
  3. 详情路由里先调 audit() 落审计，再按角色决定输出哪些字段
  4. 左侧导航加一行链接，LAYOUT() 的 extra 参数控制高亮

9.3 三个不要改坏的地方

① 遮蔽必须在服务端 不要发明「前端 CSS 隐藏」的做法。字段不出库，才算遮住了。
② 拦截不要用 403 用 200 + 中性错误文案。403 会暴露机制。
③ 计数不要放前端 配额计数、时间窗判断一旦放到浏览器，改个时钟或刷新就绕过了。

9.4 迁移到 PostgreSQL 时注意

  • quota 的联合主键改成 (user_id, day) + 唯一索引，并发下用 UPDATE … RETURNING 保证原子
  • 审计表设成只允许 INSERT，用数据库权限收回 UPDATE / DELETE
  • 遮蔽逻辑优先用视图实现，让「办公室角色查不到总额」成为数据库层的事实
